# Protectors MemoryError

`Protectors MemoryError`는 코스믹 코믹스 **프로텍터즈**를 바탕으로 제작하는 팬게임입니다. 현재는 땡땡마법사 계열의 선택형 성장과 자동 전투를 결합한 20웨이브 스테이지를 첫 목표로 개발 중입니다.

## 현재 목표

- 20웨이브를 완료할 수 있는 기본 스테이지 1개 제작
- 기본 공격 **포격**의 발사·적 처치·성장 트리 완성
- 공격 상태와 성장 조건에 따라 달라지는 강화 선택지 구성
- 최소 공개 빌드는 **포격 하나와 기본 적 하나**로 제한
- 최소 공개 빌드에서는 속성 피해와 재화 획득을 사용하지 않음

## 구현 현황

| 항목 | 상태 | 설명 |
| --- | --- | --- |
| 공격 SO / Runtime Data 분리 | 완료 | SO는 원본 수치, Runtime Data는 스테이지 중 변화하는 수치를 담당합니다. |
| 복수 공격 관리 | 완료 | `StageContext`와 `AttackController`가 활성 공격별 Runtime Data와 쿨타임을 관리합니다. |
| 포격 | 완료 | 가장 가까운 적을 향해 발사하며, 추가 탄막은 좌우 고정 각도로 발사합니다. |
| 성장 노드 | 진행 중 | 공격별 `AttackGrowthTreeSO` 기반 선택지를 구성했습니다. |
| 강화 UI | 진행 중 | `Name`/`Description` 하위 텍스트를 직접 갱신하며 선택지는 3개를 유지합니다. |
| 적 풀 / 대기열 스폰 | 완료 | 화면 내 최대 적 수를 넘긴 적은 대기열에 넣고, 빈자리 발생 시 즉시 활성화합니다. |
| 우측 공격 HUD | 완료 | 활성 공격과 쿨타임을 표시합니다. |
| 포탑 / 창덫 | 공개 범위 제외 | 데이터는 개발용으로 유지하지만 공개 스테이지에서는 활성화되지 않습니다. |
| 적 구성 | 완료 | 공개 스테이지에서는 기본 적 하나만 등장하며 속성별 피해 변화는 적용하지 않습니다. |
| 20웨이브 플레이 검증 | 예정 | Unity 플레이 모드에서 시작부터 클리어·게임 오버까지 검증이 필요합니다. |

## 핵심 구조

| 구성 요소 | 책임 |
| --- | --- |
| `GameManager` | 홈 공용 재화, 스테이지 진입과 복귀 |
| `StageManager` | 스테이지 초기화, 스폰, 웨이브, 보상, 종료 |
| `StageContext` | 한 판 동안 유효한 공격 Runtime Data 목록 |
| `AttackController` | 공격별 쿨타임과 실행기 호출 |
| `AttackGrowthTreeSO` | 강화 노드, 조건, 분기 데이터 |
| `EnemyManager` | 적 풀, 활성 적 상한, 대기열, 타겟 탐색 |
| `UIManager` | 강화 카드 생성과 선택 적용 |

## 다음 작업

1. Unity 플레이 모드에서 스테이지 시작 → 포격 발사 → 적 처치 → 강화 선택 → 20웨이브 종료를 검증합니다.
2. 게임 오버와 클리어 결과 화면이 정확히 표시되는지 확인합니다.
3. 포격 성장과 기본 적의 체력·스폰 수를 기준으로 20웨이브 밸런스를 조정합니다.
4. 공개 이후 포탑 또는 창덫의 실제 `SummonAttackExecutor`를 구현합니다.

## 개발 로드맵

| 단계 | 목표 | 완료 기준 |
| --- | --- | --- |
| 1. 기본 스테이지 | 20웨이브 스테이지 1개 완성 | 포격 성장, 적 처치, 강화 선택, 게임 오버·클리어까지 한 판이 완결됨 |
| 2. 무한 모드 | 실험 기능용 반복 전투 모드 | 신규 성장 노드, 공격 분기, 적 패턴을 빠르게 검증할 수 있음 |
| 3. 빌드 배포 | 외부 플레이 가능한 최소 빌드 | 시작·플레이·종료 흐름과 기본 UI를 오류 없이 검증 |

## 구현 메모

- 공격 원본 데이터와 스테이지 중 변하는 Runtime Data는 분리한다. 매 스테이지마다 Runtime Data를 새로 만들고 원본 데이터는 변경하지 않는다.
- 활성 공격은 독립 쿨타임을 관리한다. 투사체는 발사 당시의 Runtime Data를 보관해 다른 공격과 피해·관통·탄속을 공유하지 않는다.
- 포격은 사거리 안의 가장 가까운 적을 첫 탄의 목표로 사용한다. 추가 탄막은 좌우 고정 각도로 번갈아 발사한다.
- 스폰 수, 요청 간격, 화면 내 활성 적 상한은 Inspector에서 관리한다. 상한을 넘긴 적은 대기열에 넣고, 처치로 빈자리가 생기면 즉시 활성화한다.
- 적이 화면 밖으로 나가도 처치 흐름을 사용해 처치 수와 웨이브 진행이 누락되지 않게 한다.
- 업그레이드 카드는 버튼의 Name, Description 하위 텍스트를 직접 갱신한다. 아직 활성화하지 않은 공격은 새 공격 활성화 카드 후보에 포함한다.
- 우측 공격 HUD는 활성 공격과 실제 공격 후의 쿨타임 진행도를 표시하며, 게임이 정지된 상태에서는 숨긴다.
